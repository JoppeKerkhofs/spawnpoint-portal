# Minecraft 1.6.4 to 1.12.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Instances on Minecraft 1.6.4 up to 1.12.2 start, vanilla and with Forge, so the old packs and servers can be played.

**Architecture:** Three differences from 1.13 and newer, each handled where the newer form already is: the argument format (`launch.rs`), the asset layout of the oldest versions (`gamefiles.rs`), and Forge's older installer (`loader/forge.rs`, a second reader beside the processor one). Everything else (downloads, Java, instances, sync, panels) is untouched.

**Tech Stack:** as plan 1.

**Spec:** `docs/superpowers/specs/2026-11-19-spawnpoint-portal-design.md` (non-goals: "Versions back to 1.6.4 are wanted later, as a piece of their own (the older argument format, asset layouts, Java runtimes and Forge installer); nothing before 1.6.4"; item 7 of "Order of work"). Builds on plans 1 to 6.

## Global Constraints

All earlier plans', plus:

- Nothing before 1.6.4: refused with "Minecraft older than 1.6.4 is not supported".
- Fabric and NeoForge do not exist for these versions; asking for them is the "no build" error they already give.
- Java for these versions is Mojang's `jre-legacy` (Java 8), named by the version JSON or assumed when it names none (plan 1 already does).
- The details of old version JSONs and old Forge installers below are from memory of formats that no longer change, but check each against a saved real file before relying on it: the fixture wins.

## Review Focus

- A version between the formats (1.12.2 with a recent Forge uses the *new* installer with processors; with an old Forge, the old one): the installer is read by what is in it, not by the Minecraft version. Pinned in Task 3.
- An old Forge library that the maven only serves compressed (`.pack.xz`), which we cannot unpack: a clear "Forge <version> for Minecraft <version> needs a library this launcher cannot unpack", before the game is started, not a class-not-found crash. Pinned in Task 3.
- Legacy assets (1.6.4, 1.7.2) with no sound: the virtual copy is made and complete. Pinned in Task 2.
- A username or folder with a space in the old single-string arguments: split before filling, so a value with a space stays one argument. Pinned in Task 1.
- Joining a server on an old version: `--server` and `--port` reach the game. Pinned in Task 1.

### Task 1: The older argument format

**Files:**
- Modify: `crates/core/src/launch.rs`
- Create: `crates/core/tests/fixtures/version-1.7.10.json`, `version-1.6.4.json`

**Interfaces:**
- Consumes: plan 1's `arguments`, its placeholder table and `VersionJson.minecraft_arguments`.
- Produces: `arguments` no longer refuses a version without `arguments` when it has `minecraft_arguments`. For such a version it returns, in order:
  1. `-Xmx<memory_mb>M`
  2. the logging argument, when the version has `logging`
  3. `-Djava.library.path=<natives directory>`, `-Dminecraft.launcher.brand=spawnpoint-portal`, `-Dminecraft.launcher.version=<crate version>`, `-cp`, `<classpath>`
  4. `mainClass`
  5. `minecraft_arguments` split on spaces first, then each piece filled from the placeholder table
  6. `--server <host> --port 25565` when a server is set

  Three more placeholders: `${user_properties}` = `{}`, `${game_assets}` = the virtual assets folder (`meta/assets/virtual/<assets id>`), `${auth_session}` = `token:<access token>:<uuid>`.
  - `pub fn supported(release_time: &str) -> bool`: true from 1.6.4's release time (`2013-09-19`) on; `play::start` checks it against the manifest entry (unknown ids, such as a loader's, are not checked) and answers `Error::Unsupported("Minecraft older than 1.6.4 is not supported")`.

A version with neither form is still `Error::Unsupported`. Plan 1's test `older_than_1_13_is_refused` is replaced by the first test below.

### Task 2: Virtual assets

**Files:**
- Modify: `crates/core/src/gamefiles.rs`
- Create: `crates/core/tests/fixtures/asset-index-legacy.json` (the `legacy` index, trimmed to three objects, keeping `"virtual": true`)

**Interfaces:**
- Produces: `pub fn virtual_copies(index_json: &str, assets_dir: &Path, index_id: &str) -> Result<Vec<(PathBuf, PathBuf)>>`: for an index with `"virtual": true`, one `(objects/<2 hex>/<hash>, virtual/<index_id>/<object name>)` per object; for any other index, empty. `install` copies each pair after the assets have arrived, skipping a target that exists with the same size. Object names go through `sync::safe_path`.

### Task 3: Forge's older installer

**Files:**
- Modify: `crates/core/src/loader/forge.rs`
- Create: `crates/core/tests/fixtures/forge-1.7.10-install_profile.json`, `forge-1.12.2-old-install_profile.json`

**Interfaces:**
- Consumes: plan 2's `installer`, `InstallProfile`, `forge::install`, `maven_path`, `fetch_all`.
- Produces:
  - `pub enum Installer { Processors(InstallProfile), Legacy(LegacyProfile) }` and `pub fn read_profile(json: &str) -> Result<Installer>`: an object with an `install` and a `versionInfo` key is `Legacy`; one with `processors` or `spec` is `Processors`.
  - `pub struct LegacyProfile { pub install: LegacyInstall, #[serde(rename = "versionInfo")] pub version: VersionJson }`, `LegacyInstall { pub path: String, #[serde(rename = "filePath")] pub file_path: String, pub minecraft: String }` (`path` is the maven coordinate of Forge itself, `file_path` the name of the universal jar inside the installer).
  - `pub fn legacy_libraries(profile: &LegacyProfile) -> Result<Vec<LibraryFile>>`: every library of `versionInfo` except Forge's own (`install.path`), skipping one with `"clientreq": false`; the address is the library's `url` (default `https://libraries.minecraft.net/`) plus `maven_path(name)`; no hash (these JSONs carry `checksums` lists we do not need to trust: the file is fetched over https from the maven).
  - `forge::install` reads the profile with `read_profile`. For `Legacy`: copy `file_path` out of the installer to `meta/libraries/<maven_path(install.path)>`; write `versionInfo` to `meta/versions/<id>/<id>.json`; download `legacy_libraries` (stage `loader`); return `versionInfo`. No processors.

Add `client_req: Option<bool>` (`clientreq`) and `server_req` to `Library`.

A library that answers 404 as a plain `.jar` (some Scala libraries of 1.6.4 and 1.7.x were only published as `.pack.xz`): first try the same path under `https://maven.minecraftforge.net/` and `https://libraries.minecraft.net/`; if none has it, `Error::Unsupported("Forge <version> for Minecraft <minecraft> needs a library this launcher cannot unpack: <name>")`. Unpacking `.pack.xz` needs LZMA and Pack200, which are not on the crate list; ask the owner before going there.

`newest_forge` (plan 2) already answers for these versions from the promotions file.

    assert!(matches!(read_profile(include_str!("../../tests/fixtures/forge-1.7.10-install_profile.json")).unwrap(), Installer::Legacy(_)));

    assert!(matches!(read_profile(include_str!("../../tests/fixtures/neoforge-install_profile.json")).unwrap(), Installer::Processors(_)));
    assert!(read_profile("{}").is_err());
}
#[test] fn legacy_libraries_skip_forge_itself_and_server_only() {
    let Installer::Legacy(p) = read_profile(include_str!("../../tests/fixtures/forge-1.7.10-install_profile.json")).unwrap() else { panic!() };
    let libs = legacy_libraries(&p).unwrap();
    assert!(!libs.iter().any(|l| l.path.contains("minecraftforge/forge/")));
    assert!(libs.iter().any(|l| l.path.contains("launchwrapper") && l.url.starts_with("https://")));
    assert!(libs.iter().all(|l| l.url.starts_with("https://")));   // old profiles say http://files.minecraftforge.net: rewritten
    assert_eq!(p.version.main_class, "net.minecraft.launchwrapper.Launch");
}
