# Loaders: Fabric, NeoForge, Forge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `portal launch 1.21.1 --loader fabric|neoforge|forge[:version] --dir <folder>` starts a modded game.

**Architecture:** A loader ends up as a version JSON laid over the vanilla one. Fabric's comes from its meta service. NeoForge and Forge ship an installer jar: we read its `install_profile.json`, fetch its libraries and run its processors with our Java, then use the `version.json` inside it. `version::merge` is the one place where two version JSONs become one.

**Tech Stack:** as plan 1.

**Spec:** `docs/superpowers/specs/2026-11-19-spawnpoint-portal-design.md` (piece 4 of "Core, piece by piece"). Builds on `docs/superpowers/plans/2026-11-19-1-core-game-files-java-launch.md`.

## Global Constraints

All of plan 1's, plus:

- Loader names in our code and files: `fabric`, `neoforge`, `forge` (lower case).
- Quilt is not supported: `Error::Unsupported("the Quilt loader is not supported")`.
- Minecraft 1.13 and newer only; Forge's older installer format belongs to plan 7.
- A loader version of `None` means the newest for that Minecraft version.

## Review Focus

- A loader that has no build for the Minecraft version (`fabric` on a brand-new snapshot, `neoforge` on 1.16.5): one line naming loader and version, nothing downloaded. Pinned in Task 2 and Task 3.
- Running the same loader install twice: the second run starts no processor. Pinned in Task 5 (outputs checked by SHA-1 first).
- A processor that exits with an error: the install stops, shows the processor's last output lines, and a rerun tries it again. Pinned in Task 5.
- A data root with a space in it: processors still get their arguments whole. Pinned in Task 4 (arguments stay a `Vec<String>`; the test uses such a root).
- A library both the loader and vanilla list in different versions (ASM under Fabric): only the loader's is on the classpath. Pinned in Task 1.

### Task 1: Merging two version JSONs

**Files:**
- Modify: `crates/core/src/version.rs`
- Create: `crates/core/tests/fixtures/fabric-profile-1.21.1.json`

**Interfaces:**
- Produces: `pub fn merge(parent: VersionJson, child: VersionJson) -> VersionJson`
  - `id`, `main_class`: the child's. `inherits_from`: the parent's `id`.
  - `libraries`: the child's first, then the parent's without those whose `group:artifact` plus classifier (the `name` without its version) the child also lists.
  - `arguments`: parent's `game` then child's `game`; parent's `jvm` then child's `jvm`.
  - Everything else (`asset_index`, `assets`, `downloads`, `java_version`, `logging`): the child's when it has one, else the parent's.

### Task 3: NeoForge and Forge versions and installer download

**Files:**
- Create: `crates/core/src/loader/forge.rs`
- Create: `crates/core/tests/fixtures/neoforge-versions.json`, `forge-promotions.json` (both trimmed, keeping entries for 1.21.1, 1.20.1 and 1.16.5)

**Interfaces:**
- Produces:
  - `pub fn newest_neoforge(versions_json: &str, minecraft: &str) -> Result<String>`: from `https://maven.neoforged.net/api/maven/versions/releases/net/neoforged/neoforge` (`{"versions": [...]}`, oldest first): the last version that starts with the Minecraft version without its leading `1.` and with a trailing dot (`1.21.1` → `21.1.`, `1.21` → `21.0.`), preferring one without `-beta`. None: `Error::Other("NeoForge has no build for Minecraft <minecraft>")`.
  - `pub fn newest_forge(promotions_json: &str, minecraft: &str) -> Result<String>`: from `https://files.minecraftforge.net/net/minecraftforge/forge/promotions_slim.json`: `promos["<minecraft>-recommended"]`, else `promos["<minecraft>-latest"]`. None: the same kind of error.
  - `pub fn installer_url(kind: LoaderKind, minecraft: &str, version: &str) -> String`: NeoForge `https://maven.neoforged.net/releases/net/neoforged/neoforge/<v>/neoforge-<v>-installer.jar`; Forge `https://maven.minecraftforge.net/net/minecraftforge/forge/<mc>-<v>/forge-<mc>-<v>-installer.jar`.
  - `pub async fn installer(client: &Client, paths: &Paths, kind: LoaderKind, minecraft: &str, version: Option<&str>) -> Result<(String, PathBuf)>`: the resolved version and the installer jar at `meta/installers/<kind>-<minecraft>-<version>.jar` (add `Paths::installers()`).

Minecraft's version numbers changed to a year-based form in 2026 and NeoForge follows its own scheme for them. Before writing `newest_neoforge`, read the current list and NeoForge's versioning page; if the prefix rule above does not hold for the newest Minecraft versions, add the case and a test line for it. NeoForge for 1.20.1 lives under another artifact (`net.neoforged:forge`); it is not supported: `newest_neoforge(.., "1.20.1")` is the "no build" error.

### Task 4: The install profile

**Files:**
- Modify: `crates/core/src/loader/forge.rs`
- Create: `crates/core/tests/fixtures/neoforge-install_profile.json`, `neoforge-version.json`, `forge-1.16.5-install_profile.json`

**Interfaces:**
- Consumes: `maven_path`, `Library`, `allowed`.
- Produces:
  - `pub struct InstallProfile { pub minecraft: String, pub libraries: Vec<Library>, pub data: BTreeMap<String, DataEntry>, pub processors: Vec<Processor> }`, `DataEntry { client: String, server: String }`, `Processor { #[serde(default)] sides: Vec<String>, jar: String, classpath: Vec<String>, args: Vec<String>, #[serde(default)] outputs: BTreeMap<String, String> }`.
  - `pub struct Step { pub jar: PathBuf, pub classpath: Vec<PathBuf>, pub args: Vec<String>, pub outputs: Vec<(PathBuf, String)> }`
  - `pub struct Context<'a> { pub libraries: &'a Path, pub minecraft_jar: &'a Path, pub installer: &'a Path, pub extracted: &'a Path }` (`extracted` is where files from inside the installer are written).
  - `pub fn steps(profile: &InstallProfile, ctx: &Context) -> Result<Vec<Step>>`: the processors that run on the client (no `sides`, or `sides` contains `client`), resolved.

Resolving one value (a `data` value, an argument or an output key or value), in this order:
- `{NAME}`: replaced by the resolved `data[NAME].client`, or one of the built-ins `SIDE` = `client`, `MINECRAFT_JAR`, `MINECRAFT_VERSION`, `ROOT` (parent of `libraries`), `INSTALLER`, `LIBRARY_DIR`. Unknown name: `Error::Other`.
- `[coordinate]`: the path of that maven coordinate under `libraries`.
- `'text'`: the text without the quotes.
- A value starting with `/` (only in `data`): a file inside the installer jar; its path is `ctx.extracted` joined with it. `steps` does not extract; Task 5 does.
- Anything else: itself.

A processor's `jar` and `classpath` entries are coordinates under `libraries`. Output values are SHA-1 hashes after resolving.

### Task 5: Running the installer, and `--loader`

**Files:**
- Modify: `crates/core/src/loader/forge.rs`, `crates/core/src/loader.rs`, `crates/core/src/play.rs`, `crates/core/src/main.rs`, `README.md`

**Interfaces:**
- Consumes: Tasks 1 to 4, `gamefiles::install`, `java::ensure`, `fetch_all`.
- Produces:
  - in `forge.rs`: `pub async fn install(client: &Client, paths: &Paths, kind: LoaderKind, minecraft: &str, version: Option<&str>, java: &Path, progress: &ProgressTx) -> Result<VersionJson>`.
  - in `loader.rs`: `pub async fn profile(client: &Client, paths: &Paths, minecraft: &str, loader: &Loader, java: &Path, progress: &ProgressTx) -> Result<VersionJson>`: Fabric's profile or `forge::install`'s; not merged yet.
  - `StartRequest` gains `pub loader: Option<Loader>`.

`forge::install`, in order:
1. `installer(...)`. Read `install_profile.json` and `version.json` from the jar. Write `version.json` to `meta/versions/<its id>/<its id>.json`.
2. Download the profile's libraries with `library_files`-style resolution (stage `loader`). A library whose artifact `url` is empty is inside the installer under `maven/<path>`: copy it out to `meta/libraries/<path>` instead.
3. Extract every `data` value that starts with `/` to `meta/installers/<kind>-<minecraft>-<version>/`.
4. For each step of `steps(...)`: skip it when it has outputs and every output file matches its SHA-1. Otherwise read `Main-Class` from the `META-INF/MANIFEST.MF` of its jar and run `<java> -cp <jar;classpath> <Main-Class> <args...>` with `java.exe` beside the given `javaw.exe`, capturing output. A non-zero exit is `Error::Other("<loader> installer step <n> failed: <last 20 lines>")`. After a successful run each output is checked against its hash. Send one `Progress { stage: "loader", .. }` per step.
5. Return the parsed `version.json`.

Processors need the vanilla client jar, so `play::start` installs the vanilla files before calling `loader::profile`. New order in `start`: vanilla `version_json`; `java::ensure`; vanilla `gamefiles::install`; when a loader is set: `loader::profile`, `merge(vanilla, profile)`, `gamefiles::install` of the merged version (only the loader's libraries are new); then natives, arguments and spawn with the merged version.
